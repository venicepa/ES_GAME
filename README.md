# WebGL Deathmatch FPS

純 JavaScript + WebGL 寫的第一人稱射擊遊戲，**零外部相依**（沒有 Three.js、沒有 CDN、沒有任何圖檔），所以單檔版可以直接丟進 Claude Artifacts 或用瀏覽器開啟。

視覺走 CS 1.6 dust2 路線：沙岩牆、木箱、藍天白雲、太陽方向光 + 即時陰影、人形敵人、右下角有手的 M4A1。所有貼圖都是啟動時用 Canvas 2D 程序化生成的。

## 快速開始

專案有**兩個 renderer，共用同一份遊戲邏輯**：

| | Three.js 版（主線） | 手寫 WebGL 版（單檔） |
| --- | --- | --- |
| 進入點 | `index.html` → `src/main.js` | `dist/fps-single.html` |
| 畫面 | PBR + IBL 環境光 + ACES tonemapping + 法線貼圖 | 自寫 shader，程序化天空 |
| 3D 模型 | **可以載入 glTF / FBX**（含骨架動畫） | 不支援，只有程式生成的方塊 |
| 相依 | vendor 內的 Three.js（2.4 MB） | 零相依，單一 HTML |
| Artifacts | ✗ | ✓ |

### 單檔版（最快）

直接用瀏覽器打開 `dist/fps-single.html`，或把整份內容貼進 Claude Artifacts。

### 模組版（Three.js，本機開發）

ES Modules 不能用 `file://` 載入，需要起一個本機 server：

```bash
cd fps
python3 -m http.server 8080
# 或 npx serve .
```

然後開 http://localhost:8080

### 重新打包單檔版

改完 `src/` 之後執行（只需要 Node，不用安裝任何套件）：

```bash
node build.js
```

會把手寫 WebGL 那條線的模組依序串接、移除 `import` / `export`，輸出到 `dist/fps-single.html`。Three.js 版不參與打包。

## 標題畫面

啟動後是 **DUSTSTRIKE** 開場畫面，兩個選項：`新建遊戲`（進入房間設定）、`尋找房間`（房間列表）。

背景不是圖片，而是**遊戲場景本身的即時運鏡**：攝影機以半徑 20.5 公尺、每秒 0.042 弧度繞著地圖中心緩慢環繞，士兵擺在固定位置播待機動作。標題狀態下不跑遊戲邏輯（敵人不會移動、不會開槍），只更新動畫與攝影機。

疊在上面的是 CSS：程序化底片顆粒（SVG `feTurbulence`）、上下黑邊、左側漸層壓暗、金屬質感漸層標題、選單項目的滑入與側邊高亮。全部沒有外部圖檔，單檔版一樣能跑。

`ui.js` 對外是 `showTitle({ onNew, onFind })` / `hideTitle()` / `titleNote(text)`。

## 建立房間

`新建遊戲` 進入房間設定：

- **兩隊各 3 個位置**：反恐部隊（警察）／恐怖分子（歹徒）
- **玩家名稱**可自行輸入，會用在擊殺訊息與遊戲內名牌
- 空位有兩個動作：**「換到這裡」**（自己換隊）與 **「＋ 電腦」**（加入電腦），電腦可以移除
- 一個人也能開始，不需要填滿

陣營是真的有作用的：

- 同隊的電腦是隊友，子彈會穿過他們（射線判定跳過同隊）
- 電腦會挑**最近、有視線、不同陣營**的目標攻擊，玩家與電腦都算在內
- 擊殺算在擊殺者的隊伍分數上，兩隊電腦互打也會計分

資料模型在 `src/roster.js`（`emptyRoster` / `movePlayer` / `toggleBot` / `findPlayer`），UI 在 `ui.js` 的 `showLobby()` / `renderLobby()`。

## 連線大廳

`server/` 是 Node + WebSocket 的房間伺服器，房間狀態放在伺服器記憶體裡，所以**不同電腦之間看得到彼此的房間**。

- 建立房間、加入、換隊、加／移除電腦、換地圖、按開始，全部即時廣播給同房間的人
- 房主離線會自動移交給下一個人；房間空了 5 秒後回收（留寬限時間，避免重整頁面就掉房）
- 客戶端連不上伺服器時**自動退回離線模式**，用 `localStorage` 的本機房間，遊戲照樣能玩

伺服器位址預設是 `wss://es-game-server.onrender.com`，可以用 `?server=wss://...` 覆蓋，方便測試。

### 本機開發

```bash
cd server && npm install && node server.js   # 監聽 8787
```

客戶端從 `http://localhost` 開啟時會自動連 `ws://localhost:8787`。

### 部署

伺服器要開一個 Render **Web Service**（靜態網站不能跑後端）：Root Directory `server`、Build `npm install`、Start `node server.js`。免費方案閒置會休眠，第一個連進來的人要等冷啟動，客戶端會持續重試。

### 遊戲內同步

採**中繼式**：伺服器只轉發與記分，命中由開槍方判定。

| 訊息 | 誰送 | 內容 |
| --- | --- | --- |
| `s` | 每個玩家，約 20Hz | 位置、朝向、移動中、存活、血量 |
| `b` | **只有房主** | 所有電腦的位置與血量 |
| `f` | 開槍者 | 彈道起點與終點（讓別人看到曳光） |
| `hit` | 開槍者 | 伺服器轉給**被打的那一方**套用傷害 |
| `kill` | 判定擊殺的一方 | 伺服器加分後廣播比分與擊殺訊息 |

幾個關鍵決定：

- **電腦只由房主模擬**，其他人套用房主廣播的位置。不然每台機器的 AI 會各走各的。
- **傷害由被打的一方套用**（打到電腦則轉給房主）。這樣血量只有一個權威來源，不會兩邊各扣一次。
- **記分在伺服器**。比分是唯一必須絕對一致的東西，交給客戶端算一定會分歧。
- 遠端玩家的位置用**兩個快照做內插補間**，並刻意落後 110ms 讓封包有時間到齊，畫面才不會抖。

### 房間權限

- **進行中的房間不能加入**，列表上的按鈕會變成停用的「遊戲中」。否則加入者會落在別人房間的大廳裡，等房主一按開始就被拖進一場陣容完全不是自己設定的對戰。
- **加／移除電腦只有房主能做**，換隊每個人都可以。原本沒有權限檢查，任何人都能往別人的房間塞電腦。
- 房主的對戰結束時會把房間狀態改回「等待中」，重新變得可加入。

**可以作弊**：命中判定在客戶端，改一行 JS 就能無限傷害。跟同事玩沒差，要公開對戰就得把射線判定搬到伺服器。

## 尋找房間

`尋找房間` 是房間瀏覽器，列出目前存在的房間：房間名稱、主機、模式、人數、狀態（等待中／進行中），按「加入」會套用該房間的陣容直接開打。

**這不是連線對戰，是同一台機器上的房間列表**，實作在 `src/rooms.js`：

- 房間寫進 `localStorage`，所以重新整理不會消失
- 房主每 5 秒更新一次心跳（`updatedAt`），列表會濾掉超過 26 秒沒更新的房間——分頁當掉或直接關電腦也不會留下殭屍房間
- 關閉分頁時 `beforeunload` 會主動移除房間
- 用 `BroadcastChannel` 廣播變更，**同一個瀏覽器的其他分頁會即時看到**新房間、狀態變化與消失

實測：A 分頁開房 → B 分頁立刻看到「等待中」→ A 按開始 → B 重新整理顯示「進行中」→ B 按加入拿到同一份陣容 → A 關閉分頁 → B 的列表變成空的。

要變成真的連線對戰，把 `rooms.js` 換成打 API／WebSocket 即可，其餘介面不用動。

## 遊戲內名牌

角色頭頂會顯示名字：

- **隊友一直顯示**（綠色，穿牆可見）
- **敵人只有在準心對上時才顯示**（紅色，約 4° 內），跟 CS 一樣，不然等於送你一個透視外掛
- 距離越遠越淡，超過 42 公尺不顯示

做法是把角色頭頂的世界座標投影到螢幕座標，再定位 HTML 元素（`ui.setPlates()`），兩個 renderer 各自算投影。

## 地圖

`src/map.js` 是地圖註冊表，房間設定裡可以切換。每張地圖自帶幾何、地面、與環境（太陽方向、天空、霧、曝光），換圖時 renderer 會重建網格並重烘環境貼圖。

| 地圖 | 說明 |
| --- | --- |
| **DE_DUST**（沙漠遺跡） | 原本那張沙岩地圖 |
| **FY_ICEWORLD**（冰封競技場） | 46 × 34 的封閉冰場，兩端出生點，掩體 180 度對稱 |
| **DE_COMPOUND**（廢棄基地） | **104 × 104 公尺**的大型多房間地圖，用 ASCII 網格產生 |

`fy_iceworld` 的掩體是用 `mirrored()` 產生的——只寫一半，另一半自動做 180 度旋轉複製，所以兩隊拿到的地形**保證完全一樣**（實測 0 個不對稱方塊）。中央的十字矮牆本身就對稱，不需要複製。

冰的貼圖（`ice` 牆面、`snow` 地面）跟其他材質一樣是 Canvas 2D 程序化生成的，沒有外部圖檔。

### 用 ASCII 網格畫大地圖

手打幾百個方塊座標無法維護，所以大地圖改用網格描述，由 `fromGrid()` 展開：

```js
const COMPOUND_GRID = [
  '##########################',
  '#........................#',
  '#..#####...####......##..#',
  ...
];
```

`#` 實牆、`=` 及胸矮牆、`o` 木箱、`X` 貨櫃、`.` 通道，每格 4 公尺。展開時會做**貪婪矩形合併**：先往右擴、再整段往下擴，把相鄰同類的格子併成一個大方塊。DE_COMPOUND 的 200 多個牆格最後只變成 43 個方塊，碰撞與陰影都跟著省。

實測全圖 453 個可走格子**完全連通**（洪水填充驗證），對角最遠 52 格。

### 為什麼是這張圖

引擎只支援**軸對齊方塊**，沒有斜牆、斜坡、梯子，而且目前**走不上矮台階**（`collide()` 在落地判定前執行，只要高度範圍重疊就把玩家水平推開）。`fy_iceworld` 本來就是純方塊構成的對稱小型死鬥圖，跟這個引擎與 120 秒死鬥模式完全相符，所以能做到「就是那張圖」而不是「有點像」。

台階行走已經補上（見「移動」一節），所以需要樓梯的地圖現在做得了；斜牆與斜坡仍然不支援。

## 遊戲規則

- 回合 120 秒，計時歸零結算 CT / T 比分
- 玩家屬於 CT，每擊倒一名恐怖分子 CT +1 分
- 玩家 100 HP，被打中扣 9 HP，歸零觸發 Game Over（T +1 分）
- 爆頭四倍傷害（步槍一槍爆頭即擊殺）
- 敵人被擊倒後倒地，3 秒後在隨機座標重生
- 敵人 AI：緩慢朝玩家靠近（距離 6 公尺外），有視線時每 2～3 秒開一槍；牆與木箱會同時擋住視線與子彈

## 武器

| 鍵 | 武器 | 彈匣 | 傷害 | 射速 | 換彈 | 備註 |
| --- | --- | --- | --- | --- | --- | --- |
| `1` | USP | 12 | 34 | 單發 | 1.5s | |
| `2` | M4A1 | 30 | 26 | 連發 | 2.3s | |
| `3` | AWP | 5 | 115 | 單發 1.4s | 3.0s | 右鍵切換開鏡（約 4 倍），一槍斃命；開鏡時移動剩 38%，開火後自動退鏡，再按右鍵重新開鏡 |
| `4` | M3 | 8 | 21 × 9 顆 | 單發 0.85s | 3.2s | 一次打出 9 條彈道，近距離全中約 189 傷害 |

備彈無限，換彈只消耗時間。

彈道方向在**套用後座力之前**計算：`player.dir` 會讀 `viewPitch`（含 `recoil`），若順序反過來，子彈會往槍口跳上去之後的方向飛而不是你瞄的方向——後座力越大的槍偏得越誇張。散彈槍的多顆彈丸傷害會**先依敵人累加再一次結算**，所以一槍只會產生一則擊殺訊息。

## 檔案結構

```
fps/
├── index.html            Three.js 版進入點（含 importmap）
├── build.js              把手寫 WebGL 那條線打包成單檔 HTML
├── assets/               放你自己的 3D 模型（見下節），預設是空的
├── vendor/               Three.js r170 + 需要的 addons，離線可用
├── dist/
│   └── fps-single.html   打包產物，可直接開啟 / 貼到 Artifacts
└── src/
    ├── game.js           遊戲主迴圈、輸入、命中判定、計分、狀態機（與 renderer 無關）
    ├── map.js            地圖方塊、AABB 碰撞解算、射線偵測、隨機重生點
    ├── player.js         移動、視角、武器彈藥、後座力、頭部晃動
    ├── enemy.js          敵人 AI、視線判定、走路狀態、死亡與重生
    ├── ui.js             HUD：準心、命中標記、血量、彈藥、計分、擊殺訊息、結算畫面
    ├── textures.js       程序化貼圖（沙岩、沙地、木箱、貨櫃、雲）與法線貼圖生成
    ├── render-three.js   Three.js renderer：PBR、IBL、陰影、模型載入
    ├── render-gl.js      手寫 WebGL renderer
    ├── gl.js             手寫 WebGL 封裝：shader、陰影貼圖、程序化天空、矩陣運算
    ├── main.js           Three.js 版 bootstrap
    └── main-gl.js        單檔版 bootstrap
```

`game.js` 只呼叫 `renderer.render(state)`，兩個 renderer 都實作同一個介面，所以遊戲規則只有一份。

### 模組職責

- **`gl.js`** — 唯一碰 WebGL API 的地方。兩個 shader program（主畫面 / 深度），`Renderer` 提供 `cube()`、`basis()`（任意朝向方塊）、`segment()`（彈道）、`sky()` 四種繪製方式，其餘模組不需要知道 GL 細節。
- **`textures.js`** — 每張貼圖都是 256×256 的 Canvas 2D 程序化繪製，沒有任何外部圖檔，所以單檔版仍然是單檔。
- **`map.js`** — 地圖是一組 AABB 方塊。`collide()` 做圓柱 vs AABB 的水平推出，`rayWalls()` 提供子彈與 AI 視線共用的射線查詢，`randomSpawn()` 找出不卡牆、離玩家夠遠的重生點。
- **`player.js`** — 純狀態機，不直接讀 DOM；`update(dt, keys)` 收一個按鍵表，`tryShoot()` 回傳帶散佈的射線方向或 `null`。
- **`enemy.js`** — 每隻敵人自行管理靠近 / 開火 / 死亡計時，開火透過 callback 通知外層，不知道玩家怎麼扣血。
- **`ui.js`** — 自行建立 HUD DOM 與樣式，對外只有 setter，`index.html` 因此只需要一個 `<canvas>`。底部列參考 CS2：護甲圖示、大字血量、血量下方的細長血條、中央的隊伍徽章（`setTeam('ct' | 't')` 會同時換徽章與 `--team` 主色）、右側武器彈藥。徽章是內嵌 SVG，沒有外部圖檔。
- **`game.js`** — 組裝以上模組、跑主迴圈、處理 menu / play / paused / over 四種狀態，只透過 `renderer.render(state)` 跟畫面溝通。
- **`render-three.js` / `render-gl.js`** — 兩個可互換的 renderer，實作同一個 `render(state)` 介面。

## 換成真正的 3D 模型

**預設已經附齊了**（來源與授權見 `assets/SOURCES.md`）：

- `enemy.glb` — three.js 範例的 Mixamo 士兵，含 Idle / Walk / Run 動畫
- `rifle.glb` / `pistol.glb` — Quaternius「Ultimate Guns Pack」的 CC0 低多邊形槍械

敵人手上的步槍是把 `rifle.glb` clone 後掛到右手骨骼上，不需要額外檔案。

Three.js 版啟動時會檢查 `assets/`，**有就用、沒有就退回程式生成的方塊**。換檔案即可生效，不用改程式：

| 檔案 | 用途 |
| --- | --- |
| `assets/rifle.glb` | 第一人稱步槍（同時是敵人手上那把） |
| `assets/pistol.glb` | 第一人稱手槍 |
| `assets/enemy.glb` | 敵人角色（支援骨架動畫） |

支援 `.glb` / `.gltf` / `.fbx`。敵人模型會自動依 `ASSETS.enemy.height`（預設 1.85 公尺）縮放。

動畫片段用名稱比對，含 `idle`／`walk` 或 `run`／`death` 或 `die` 的 clip 會自動接上待機、行走、死亡三種狀態（`TPose` 之類的綁定姿勢會被跳過）。沒有死亡動畫時，模型會凍結目前姿勢並向前倒下。

模型面向不對就改 `ASSETS.enemy.rot`；手上的槍位置用 `gunPos` / `gunRot` / `gunBone` 調整，骨骼縮放會自動補償。

### 第一人稱的手與換彈動作

載入槍械模型後會生成一雙**真的手**：從 `enemy.glb`（Mixamo 骨架）的蒙皮網格切出手掌與五指，烘成靜態網格重複使用，所以不需要額外的手部模型檔，也沿用士兵的手套貼圖。

烘的流程（`bakeHands()`）：

1. 依 skin weight 找出每個頂點的主導骨頭，保留 `*Hand*` 與 `*ForeArm*` 的三角形。
2. 用手指與拇指的質心推出手的座標系，把幾何轉成「手指朝 +Z、拇指朝 +Y」的標準姿勢，之後擺放只要調角度。
3. 手指繞「手掌側向軸」彎起來成握姿。該軸在每根指骨的 local 空間方向都不同，所以把世界空間的側向軸換算進各骨頭再轉，不用硬猜 x/y/z。
4. 量 bounding box 正規化成真人尺寸（骨骼矩陣帶著模型自己的單位縮放，不能直接套 `enemyScale`）。
5. 在前臂切口接一截袖子（`SLEEVE_LENGTH`），長到一定超出畫面邊緣。**方向是從幾何算出來的**：取切口附近與稍微往內兩段的頂點質心，兩點相減就是前臂的真實軸向；直接沿 -Z 延伸會因為手腕有角度而出現折角。握點離攝影機較遠的長槍（狙擊）少了這截就會看到懸空的斷面。

**手腕擺在畫面外，手指瞄準握把**——這是真實 FPS 的做法。手臂因此從畫面底部進來，手腕的切口永遠不會被看到。

定位方式是 `at`（手掌要貼的位置）＋ `aim`（手指指向）＋ `up`（控制掌心的滾轉），由 `aimHand()` 換算：先定旋轉，再把旋轉後的手掌質心偏移扣掉反推手腕座標。**手掌質心是從烘出來的網格量的**（掌骨主導的頂點），不是猜的，所以手真的貼在槍上而不是浮在旁邊。

`at` 的座標也是量出來的：沿槍身分箱掃過模型頂點，取每一段的 y 範圍，就能看出握把、彈匣、護木各在哪：

```
z=-0.81  y:-0.102..-0.044   護木（底部 -0.102）
z=-0.68  y:-0.295..-0.044   彈匣（垂到 -0.295）
z=-0.52  y:-0.228..-0.021   握把（底部 -0.228）
```

右手固定握把，左手做程序化的換彈動作（不需要動畫檔）。時間軸依武器的 `reloadTime` 正規化成 0→1：

| 進度 | 動作 |
| --- | --- |
| 0.00–0.14 | 左手從護木移到彈匣 |
| 0.14–0.26 | 退出舊彈匣 |
| 0.26–0.42 | 手往下離開畫面 |
| 0.42–0.56 | 取新彈匣（畫面下方看不到） |
| 0.56–0.79 | 帶著新彈匣回來並推入（此時手上會出現一個彈匣方塊） |
| 0.86–0.94 | 拉槍機並放開 |
| 0.94–1.00 | 回到護木 |

關鍵點都寫在 `ASSETS.weapons[*]`：

```js
grip: {
  right: { at: [0.305, -0.180, -0.505], aim: [-0.20, 0.58, -0.79], up: [0, 0, -1] },
  left:  { at: [0.262, -0.158, -0.808], aim: [0.50, 0.66, -0.56], up: [0, 0, -1] },
  mag: [0.27, -0.295, -0.680],  // 彈匣井
},
charge: [0.30, -0.075, -0.50], // 槍機拉柄
magSize: [0.05, 0.20, 0.07],   // 手上彈匣的尺寸
```

換槍模型時調這幾個座標就好，動作曲線不用改。

沒有 `enemy.glb` 時會退回程式生成的方塊手；單檔版一律用方塊手，也不套用這段動作。

想調整握姿：`ARM_LENGTH`（手臂長度）與 `CURL`（手指彎曲程度）在 `src/render-three.js` 最上方。

槍械**不需要手動算縮放**：填 `length`（公尺），載入器會量 bounding box 自動縮放並置中。轉向用 `axes` 指定模型的三個軸各自對應到世界的哪個方向，比猜 Euler 角度順序可靠：

```js
export const ASSETS = {
  weapons: {
    rifle: {
      url: 'assets/rifle.glb',
      length: 0.86,                                   // 目標長度（公尺）
      pos: [0.27, -0.15, -0.68],                      // 攝影機空間位置
      muzzle: [0.27, -0.088, -1.10],                  // 槍口火光位置
      axes: { x: [0, 0, -1], y: [0, 1, 0], z: [1, 0, 0] },
      grip: {                                          // 手的錨點
        right: [0.285, -0.238, -0.56],
        left: [0.272, -0.175, -0.92],
        mag: [0.27, -0.30, -0.65],
      },
      charge: [0.30, -0.075, -0.50],                  // 槍機拉柄
      magSize: [0.05, 0.20, 0.07],
    },
  },
  enemy: {
    url: 'assets/enemy.glb', height: 1.85, rot: Math.PI,
    gunBone: /RightHand$/, gunPos: [0, 0.08, 0.01], gunRot: [-0.15, 0.05, 0.15],
  },
};
```

不確定新模型的朝向時，載進來量各材質的世界座標 bounding box：延伸最長的軸是槍身長度、彈匣所在的那側是下方。

### 動畫：一個檔案一段，分開放

Mixamo 一次只能下載一段動畫，所以敵人動畫支援**多檔載入**。放這些檔名就會自動接上：

| 檔案 | 狀態 |
| --- | --- |
| `assets/anim-idle.fbx` | 站立待機 |
| `assets/anim-walk.fbx` | 前進 |
| `assets/anim-fire.fbx` | 開火（一次性，開槍瞬間播 0.55 秒） |
| `assets/anim-death.fbx` | 倒地（只播一次並停在最後一格） |

沒放的檔案會退回模型本身內建的 clip。骨骼名稱會自動正規化比對（`mixamorig:LeftArm` ↔ `mixamorigLeftArm` ↔ `LeftArm` 都能對上），所以動畫檔和角色檔來源不同也能接。

#### Mixamo 下載設定

角色本體（`assets/enemy.fbx`，記得同步改 `ASSETS.enemy.url`）：
- Format: **FBX Binary (.fbx)**
- Skin: **With Skin**

各段動畫（`anim-*.fbx`）：
- Format: **FBX Binary (.fbx)**
- Skin: **Without Skin**
- Frames per Second: **30**，Keyframe Reduction: **none**

搜尋關鍵字用 **rifle** 比 gun 精準：`Rifle Idle`、`Walking With Rifle`、`Firing Rifle`、`Death From Front`。

### 去哪裡拿模型

- **角色**：Mixamo（Adobe，免費帳號）— 現成人物 + 自動綁骨 + 大量動作。
- **槍械**：Mixamo **沒有**道具模型，只有角色和動作。槍要去 Poly Pizza、Sketchfab（可篩 CC0）、Fab 免費區、Quaternius 找。
- **自己用 Blender 做** — 匯出時選 glTF 2.0（`.glb`）。

命中判定用的是固定膠囊 / AABB（`enemy.js` 的 `bounds()`、`headBounds()`），跟模型外觀無關，所以換模型不會影響手感或準度。

## 機器人尋路

`src/nav.js` 提供 A*：

- 導航網格是**取樣建立**的（每 2 公尺一格，用 `blocked()` 判定），不依賴地圖怎麼畫，所以三張圖都適用
- 8 方向移動，斜走時兩側都必須通（不切角）
- 路徑會做**拉直**：每幀從目前位置往前找最遠一個還有視線的路徑點，避免貼著格線走出鋸齒
- 看得到目標就直線衝，看不到才走路徑；目標移動超過 5 公尺或過 1.2～1.8 秒才重算

**目標選擇**：優先打看得見的敵人，都看不見就鎖定最近的一個主動追過去。只用「有視線」當條件的話，大地圖上雙方互相看不到，機器人會整場站著不動——這在小地圖看不出來。

**不會僵在原地**：

- `advancing = dist > KEEP_DISTANCE || !los` —— 看不到目標時一定要移動。只看距離的話，會卡在「已經夠近但沒有視線」的死角站著不動。
- 距離夠近且看得見時改成**橫移**（每 0.7～2 秒換邊），不是停住。
- **卡住偵測**：眼睛看得到不代表走得過去，中間可能隔著胸高掩體。走直線時若 0.45 秒內幾乎沒位移，就強制改走 A* 兩秒——導航網格會把矮牆算進去，繞得過去。

## 移動

- 重力 21 m/s²，跳躍初速 6.4 → 跳躍高度約 0.82 公尺
- 蹲下時視線降到 0.95 公尺、碰撞高度降到 1.05、移動速度剩 45%
- **蹲跳**：空中按 `Ctrl` 會把腳往上收、頭維持原位，多出約 0.7 公尺的落腳高度，所以跳得上 1.25 公尺高的木箱（跟 CS 一樣，不必把跳躍調成超人）
- 頭頂被擋住時站不起來，會維持蹲姿
- 可以站在木箱、貨櫃、矮牆上；`map.js` 的 `groundHeight()` / `ceilingHeight()` 提供腳下與頭頂的查詢
- **台階**：水平被擋住時會試著把腳抬高 ≤0.42 公尺再走一次（`moveWithStep()`），玩家與機器人共用。沒有這段的話 `collide()` 會在落地判定之前把人水平推開，連 30 公分的階梯都上不去

**頭頂偵測用的圓柱比身體細**（`HEAD_RADIUS`）。因為 `collide()` 會把玩家推到離箱子正好等於半徑的位置，如果兩者同半徑，只要貼著任何高箱子站就會被判定頭上有東西而強制蹲下、連帶不能跳。

## 渲染做法

### Three.js 版

- 方向光 + 2048 shadow map（PCFSoft），shadow camera 跟著玩家移動
- 天空用 Three 的 `Sky`（Preetham 大氣散射），再用 `PMREMGenerator` 把它烘成環境貼圖當 IBL 環境光，雲是另一層程序化 fbm 貼圖的高空平面
- 貼圖在 CPU 端由亮度推出法線貼圖（`normalFromHeight`），所以牆面磚縫有立體感
- 地圖依材質合併成 4 個 mesh，UV 依方塊實際尺寸縮放，貼圖不會被拉伸
- ACES filmic tonemapping，粒子與彈孔用 `InstancedMesh`
- 第一人稱武器在獨立 scene / camera 用較窄 FOV 重畫，清一次 depth buffer，不會穿牆

### 手寫 WebGL 版

- **陰影**：太陽方向做一次 2048×2048 正交深度 pass，深度打包進 RGBA8（不需要 depth texture 擴充功能），主 pass 用 3×3 PCF 取樣；用 normal offset 消除 shadow acne。
- **天空**：以攝影機為中心的大方塊，在 fragment shader 裡依方向算漸層、太陽光暈，雲是 5 層 fbm 雜訊並隨時間飄移。
- **貼圖座標**：頂點 shader 依面法線做平面投影，UV 直接取自世界尺寸，所以同一張貼圖貼在任意大小的方塊上都不會被拉伸。
- **第一人稱武器**：主場景畫完後清一次 depth buffer，用較窄的 FOV 與單位矩陣 view 重畫，武器座標直接寫在攝影機空間，不會穿牆也不會被場景 FOV 拉變形。

## 效能

畫面成本幾乎都在片段著色（幾何只有 ~4,900 個三角形、7 個 draw call），所以調整重點是像素數與陰影：

- **解析度上限 `devicePixelRatio` 1.5**（不是 2）。Retina 全螢幕在 dpr=2 是約 590 萬像素/幀，壓到 1.5 少掉約 44%。
- **動態解析度**：`adaptResolution()` 追蹤實際幀時間，超過 23ms 就降一階（最低 0.75），低於 13ms 再升回去，調整後鎖約 90 幀避免在臨界值來回震盪。
- 陰影用 `PCFShadowMap` + 1024²（原本是最貴的 `PCFSoftShadowMap` + 2048²）。
- `devicePixelRatio ≥ 1.5` 時關閉 MSAA，高 DPI 本來就把鋸齒縮小了。

想再省的話：`src/render-three.js` 最上方的 `MAX_PIXEL_RATIO`、`SHADOW_SIZE` 都可以再往下調；把 `sun.castShadow` 關掉省最多。

## 已知限制

- 子彈為 hitscan，不模擬彈道下墜
- 敵人不會找掩體，只會直線靠近
- Three.js 版需要瀏覽器支援 importmap 與 WebGL 2；單檔版只需要 WebGL 1
- 兩版都需要 Pointer Lock API
